# Languages

## Model

- Locales: `siteConfig.locales` and `siteConfig.defaultLocale` in
  `src/lib/config.ts`. The default keeps unprefixed URLs; others live under
  `/<code>/` (ADR 0026).
- Interface text: `src/i18n/messages/<code>.ts`. `en.ts` defines every key;
  others may be partial and fall back per key (ADR 0027).
- Content: optional sibling files `*.<code>.md` (ADR 0028,
  [content-authoring.md](content-authoring.md#translations)).
- Reader choice: remembered, suggested, never redirected (ADR 0029).

## Add a language

1. Add `{ code: 'fr', name: 'Français', dir: 'ltr' }` to `LOCALES`.
2. Create `src/i18n/messages/fr.ts` exporting `fr: Partial<Catalog>`, and
   register it in `messages/index.ts`. Start with a few keys; the rest stays
   English, marked `lang="en"`.
3. Optionally translate pages and posts with `*.fr.md` files.
4. `./check.sh`. The placeholder test fails if a translation drops or renames
   a `{placeholder}`.

`missingKeys(catalogs, 'en', 'fr')` lists what is left to translate. The
"Spanish catalog is complete" test is the pattern for declaring a locale
finished.

## Remove a language

Delete it from `LOCALES`; its `/code/` tree disappears on the next build.
Its catalog and `*.code.md` files then fail validation until removed too.

## Plurals, numbers, dates

Plural messages are maps such as `{ one: '{count} post', other: '{count}
posts' }`, selected by `Intl.PluralRules` (`zero`, `two`, `few`, `many` are
available where a language needs them). Numbers use `Intl.NumberFormat`,
dates `Intl.DateTimeFormat` with `dateStyle: 'long'`, language names
`Intl.DisplayNames`.
